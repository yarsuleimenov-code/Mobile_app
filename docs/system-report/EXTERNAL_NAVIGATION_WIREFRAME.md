# MOB — Внешняя навигация

Статус 2026-10-05: реализация и дополнительные UI/UX-улучшения приняты owner; push в main разрешён. Scope — существующий hi-fi прототип, без собственного routing/map SDK.

## Сценарий и UX

- Navigate и Copy address у полного адреса конкретной остановки на Home (Today's stops), Tasks, Pickup, Dropoff и Order details/Team contacts. Адрес не обрезается, размер 16 px; улица визуально отделена от города/индекса по первой запятой без изменения копируемого назначения. Navigate — синяя вспомогательная кнопка с иконкой. В Home/Tasks компактный блок не повторяет операцию/время/номер остановки и Opens Google Maps; пояснение остаётся в подробных экранах, причина блокировки показывается всегда. Область действий минимум 48 CSS px в web-прототипе.
- Order details открывает карточку с начала; Team contacts из Pickup/Dropoff сохраняет order/operation/stop и добавляет focus=team для прокрутки и keyboard focus на список контактов. При отсутствии адреса Contact team доступен и для существующей остановки. Неоднозначный выбор по-прежнему ведёт к выбору остановки, а не к подстановке первой.
- Подтверждение Copy address / Copy order summary меняет текст кнопки без добавления строки или сдвига содержимого. Для адреса ширина кнопки сохранена; ручной fallback при отказе Clipboard остаётся доступным.
- Navigate — HTTPS-ссылка Google Maps directions с api=1, destination, travelmode=driving, dir_action=navigate, без origin. Отправляется только адрес, не номер заказа/контакт/OTP/содержимое груза. Новая вкладка использует noopener/noreferrer; исходный экран остаётся открытым.
- Карты используют своё местоположение/разрешения и могут открыть приложение либо web-preview. Собственного запроса GPS, выбора навигатора, ETA и карты внутри прототипа нет. Не заявляем «Navigation started»: браузер не подтверждает запуск навигации.
- Copy address копирует только полный адрес. Copy order summary остаётся отдельным действием. При отказе Clipboard доступно read-only поле с выделением для ручного копирования.
- Назначение связано с order + operation + stopId. Из списка передаётся сама остановка; в операциях используется точное совпадение. При нескольких кандидатах: Select a stop to navigate → Select stop in Order details → Order stop. Неверный stopId или пустой адрес не создаёт активную ссылку; при отсутствии остановки доступен Team contacts. Первую остановку автоматически не подставляем.
- На Home Navigate недоступен без действующего завершённого Pre-trip либо после закрытия цикла Post-trip. Адрес можно копировать. Существующие ручные Pickup/Dropoff и Tasks не получили новый departure-gate: открытие карт не является разрешением эксплуатации автомобиля.
- Перед обычным нажатием Navigate в Pickup/Dropoff выполняется синхронное сохранение текущего черновика. При ошибке ссылка не открывается; экран сообщает о необходимости проверить storage и повторить. Locked Delivery не перезаписывается. Введённый, но ещё не открытый другой номер заказа блокирует Navigate старого заказа.
- Не меняются статусы остановок, прибытие, eBOL/POD или порядок маршрута. Действия не добавлены в Signature/OTP/POD.

## Ограничения и основание

Текущие адреса — публичные объекты для демонстрации, не клиентские назначения. Навигация требует возможностей внешнего приложения и его сети/офлайн-карт. Обычная driving-ссылка не передаёт высоту/массу/коммерческие ограничения автомобиля; это не truck-safe routing. Перед поездкой водитель должен проверить назначение и ограничения движения. Production truck routing — отдельный scope.

Основание: [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started) — универсальные ссылки без API-ключа, navigation или preview в зависимости от устройства/геопозиции; [Android touch targets](https://support.google.com/accessibility/android/answer/7101858?hl=en) — ориентир 48 dp для будущего mobile client. Web CSS px не заявляются равными native dp.

Основные файлы: externalNavigationDomain.ts/test, StopNavigation.tsx, CargoHomeScreen, TasksScreen, PickupCaptureScreen, DropoffVerifyScreen, TeamContactsCard и cargo.css. Общий компонент использует существующие маршрут и разрешение остановки; новой системы хранения или архитектуры нет.
