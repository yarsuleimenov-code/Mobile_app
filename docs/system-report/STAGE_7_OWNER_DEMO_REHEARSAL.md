Дата репетиции: 2026-09-02. Сверка статуса: 2026-09-18. **Код Этапа 7 включён в `main`** коммитом `762ffb5`; готовность к production и отдельная бизнес-приёмка owner этим не подтверждаются.
Исторический baseline этапов 5–6 — `8756a6f`; более поздние изменения: Administration (`8f756a5`) и email-копия Pickup eBOL (`4f9b552`).

## Цель и границы

Аудитория — owner; пользователь экранов — водитель/сотрудник Pickup и Dropoff. Проверяем понятность пути от заявки до POD, исправление заказа на месте, исключения и продолжение работы после локального сбоя.

Критерий технической готовности: семь сценариев проходят два раза подряд с чистого старта, без правки кода и ручного изменения browser storage во время репетиций. Подписанный исходный факт и PlaceID остаются неизменными. Критерий бизнес-приёмки — отдельный просмотр и решение owner.

Backend/SQL, реальные фото/upload, offline-запуск приложения, принтер, email/PDF, два физических устройства и полевой пилот не входят в этап. Все данные вымышленные; ведущий объясняет это устно до показа. В рабочих экранах нет demo/mock/simulate-пометок.

## Подготовка ведущего

1. Запустить из корня `pnpm --dir wireframe build`, затем `pnpm --dir wireframe preview --port 4173`. Если preview уже работает, достаточно новой сборки.
2. Открыть More → Administration или напрямую `http://127.0.0.1:4173/Mobile_app/#/more/demo`. Вход из More восстановлен по запросу owner от 2026-09-03.
3. Нажать **Reset all mock data** и подтвердить предупреждение. Удаляются локальные черновики, подписи, документы, фото-метаданные, история печати и сценарные настройки этого приложения; восстанавливается исходный набор заявок. Reset необратим для этих локальных данных. Cancel ничего не удаляет.
4. Выбрать нужный preset; переключиться на рабочий экран до демонстрации owner. Роль, филиал NJ1, сеть и устройства выставляются предсказуемо. Пресеты не подписывают новые операции.
5. Для повторной полной репетиции снова выполнить Reset. Повторное открытие одного preset **без Reset сохраняет правки и документы**, а не перезаписывает их.
6. Для штатных подтверждений можно использовать Morgan Lee / Chris Adams; нажимать Insert signature и подтверждение каждой стороны отдельно.

## Реализованные изменения

- Семь отдельных order-presets с заполненными грузами, фото, order details и Spoke stop. Для обычного Pickup создаётся только draft: открытие формы не записывает факт Pickup. Единственная готовая подпись — исторический original в Supplemental preset.
- Сохранённая работа имеет приоритет перед fixtures. Повторное открытие не создаёт дубли заказов/stop; ошибка установки preset показывает сообщение и не переводит пользователя на частично подготовленный экран; предусмотрен rollback записей.
- Pickup: ввод другого Order # не переносит старые места/ID; Open selected order загружает собственный черновик новой заявки. Пустой состав/фото и ошибка хранения объясняют disabled Continue.
- Review хранит ревизию исходного draft. После редактирования нужен повторный Continue из черновика; подпись устаревшего review запрещена. Документированное повреждение сохраняется при обновлении неподписанного evidence.
- Locked Pickup получил Continue to Dropoff / View POD. Прямой Back без внутренней истории возвращает Home. Переход из отсутствующего Pickup record сохраняет номер заказа.
- Dropoff: поиск синхронизирован с URL и заголовком; проверки/фото загружаются отдельно для каждого заказа. Пока введённый номер отличается от показанного, подтверждение запрещено.
- Ошибка записи Delivery review не показывает успех и не завершает Dropoff; повтор доступен после восстановления хранения.
- Незавершённое Supplemental и несовпадение подписанного состава блокируют Delivery. Empty evidence нельзя подписать.
- Служебные preset-карточки оформлены отдельно; рабочая компактная строка Qty/L/W/H/Weight сохранена.

Код: `demoRehearsal.ts`, `pickupReviewState.ts`, соответствующие screens/stores/domains и scoped CSS. Добавлены 16 unit-тестов пресетов/защит; два старых Delivery fixtures дополнены фактически добавленными местами. Backend, SQL и зависимости не менялись.
