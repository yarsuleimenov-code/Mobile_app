# MOB — Post-trip inspection

Дата: 2026-10-05. Статус: реализовано в hi-fi прототипе и принято owner; push в main разрешён 2026-10-05.

## Сценарий

После завершённого Pre-trip на Home появляется Post-trip inspection → Start/Continue/View. Экран `#/post-trip-inspection` показывает Van 08 · Extended Van · NJ1. Осмотр доступен без загрузки маршрута; складской Interstate gate не добавляется.

1. Check: семь существующих групп автомобиля и Company equipment & tools. Для каждой — Pass/Issue. Issue обязательно имеет текстовое описание, до 1000 символов.
2. Photos: Front, Rear, Driver side, Passenger side, Dashboard. Пять обязательных ракурсов, без галереи; Camera unavailable отключает capture.
3. Review: ответы, дефекты и фото; водитель подтверждает достоверность записи, не исправность автомобиля. Если загруженный маршрут содержит остановки без locked Pickup/Delivery handoff, требуется отдельное подтверждение, что они остаются незавершёнными и должны быть сообщены диспетчеру.
4. Complete Post-trip: Completed либо Completed — issues reported. При Issue автомобиль Needs attention. Дефекты не блокируют сдачу отчёта.
5. Итог read-only: времена обоих осмотров, checklist, дефекты, фото-маркеры, число подтверждённых незавершённых остановок и связанный Pre-trip.
6. Home → Start next vehicle cycle сохраняет пару в Previous vehicle inspections и открывает новый Pre-trip. Старый допуск не используется повторно; загруженные остановки на Home снова недоступны до нового успешного Pre-trip.

## Границы и сохранение

- `zaberman-vehicle-inspections:v1` хранит текущую пару и историю атомарной записью. Старый `zaberman-pre-trip-inspection:v1` читается как legacy при отсутствии нового ключа. Активный Pre-trip с четырьмя фото требует Dashboard и новое подтверждение; историческая пара с завершённым Post-trip сохраняется без изменений. Legacy-ключ не удаляется.
- Ошибка localStorage показывает предупреждение и не меняет последнее сохранённое состояние. Завершение/новый цикл не объявляются успешными при ошибке записи.
- Завершённые Pre-trip и Post-trip не редактируются. При новом цикле показывается предупреждение о дефектах предыдущего Post-trip; это не механизм подтверждения ремонта.
- Прототип не хранит реальные изображения. Capture сохраняет только ракурс. Повторный capture не создаёт бинарный файл или самостоятельный timestamp снимка.
- Число незавершённых остановок выводится из локальных locked eBOL по типу операции, а не из реального статуса Spoke. При незагруженном маршруте его остановки неизвестны; проверка не подставляет фиктивный маршрут.
- Осмотр не меняет заказы/маршрут, не отправляет alert диспетчеру, не закрывает Interstate Trip и не считает смену/зарплату. Прямые Pickup/Dropoff и Tasks остаются существующими входами прототипа; новый gate относится к загрузке и открытию остановок с Home.
- Компания/филиал/автомобиль статические; список Company equipment общий, не подтверждённый инвентарный справочник. Реальная камера, backend, ремонт, vehicle assignment и server audit вне scope.
- Administration → Reset all mock data очищает оба ключа и историю.
- Pre-trip сохраняет семь проверок и пять обязательных фото, включая Dashboard. Расширение проверки корпоративного оборудования — следующая принятая задача.

## Проверка

Domain tests: обязательные поля, пять фото, описание Issue, допустимость завершения с дефектом, незавершённые остановки, immutable completion, архив и новый цикл, refresh, legacy restore, malformed storage.

Браузер: Chrome, `http://127.0.0.1:5173/Mobile_app/`, 390×844 и 1440×1000. Пройден Pre-trip → загрузка маршрута → Post-trip с дефектом → пять фото → обязательное подтверждение оставшихся остановок → ошибка сохранения и retry → read-only результат после refresh → новый Pre-trip → просмотр архивной пары. Дополнительно пройдены Camera unavailable/recovery через Administration и завершение без загруженного маршрута. Нет ошибок приложения в console/pageerror; нет горизонтального overflow на проверенных viewport. Реальные мобильные устройства/камера не проверены.

Автоматическая проверка: 136 wireframe tests пройдены (из них 12 Post-trip и 5 Pre-trip), TypeScript и Vite app build пройдены; документация VitePress собрана. Vite сохраняет предупреждение о размере основного bundle >500 kB; code splitting не входит в эту задачу.
