## 1. Целевой результат

Документация должна публиковаться вместе с прототипом в одном GitHub Pages deployment:

- приложение: `https://yarsuleimenov-code.github.io/Mobile_app/`;
- русская инструкция: `https://yarsuleimenov-code.github.io/Mobile_app/help/ru/`;
- английская инструкция: `https://yarsuleimenov-code.github.io/Mobile_app/help/en/`.

Пользовательский вход: `More → Help & Instructions`. Из документации должна быть доступна ссылка возврата в приложение.

### Критерии готовности

- RU и EN открываются по постоянным прямым ссылкам;
- страницы читаются на мобильном экране без горизонтальной прокрутки основного содержимого;
- приложение и документация входят в один deployment artifact;
- Markdown-файлы проекта остаются единственным редактируемым источником;
- прямые ссылки, изображения и переход между приложением и инструкцией работают;
- существующая бизнес-логика приложения не меняется.

## 3. Единственные исходники

Редактируемая документация сохраняется без переноса:

```text
docs/mobile-app/                  # руководство и бизнес-документы
  ru/                             # русская версия
  images/                         # общие скриншоты
knowledge-base/mobile-app/        # статьи базы знаний
  ru/                             # русская версия
```

Правила:

1. Английская версия хранится в корне соответствующего каталога, русская — в `ru/`.
2. Опубликованный HTML и подготовленный для VitePress контент генерируются автоматически.
3. Сгенерированные файлы не редактируются и не считаются источником истины.
4. `open-questions.md` не копируется, не публикуется и исключён из публичного Git-коммита; системные документы не входят в основную пользовательскую навигацию.
5. Перенос или дублирование текущих Markdown-файлов на подготовительном этапе не требуется.

## 4. VitePress

- установлена стабильная версия `vitepress@1.6.4`;
- корень сайта: `wireframe/docs-site/`;
- исходный каталог VitePress: `wireframe/docs-site/content/`;
- production output: `wireframe/dist/help/`;
- base path: `/Mobile_app/help/`;
- включены clean URLs и локальный поиск;
- cache, временный контент и стандартный VitePress output исключены из Git.

VitePress 1.6.4 содержит необязательную зависимость Algolia DocSearch с peer-диапазоном React до 18. В проекте используется встроенный локальный поиск, поэтому DocSearch не активируется и предупреждение не влияет на приложение или сборку документации. Preview-версия VitePress 2 в проект не добавлялась.

## 5. Подготовка RU/EN контента

Скрипт `wireframe/scripts/prepare-docs.mjs`:

1. проверяет наличие обязательных документов;
2. очищает только генерируемый `docs-site/content`;
3. собирает английскую и русскую версии;
4. переносит Knowledge Base и изображения;
5. преобразует `README.md` в `index.md`;
6. исключает `open-questions.md` из входов и результата сборки;
7. переписывает ссылки между публикуемыми документами;
8. преобразует ссылки на код и системные документы в GitHub-ссылки;
9. завершает сборку ошибкой при неизвестной локальной ссылке;
10. проверяет обязательные выходные файлы.

Команда: `pnpm docs:prepare`.
