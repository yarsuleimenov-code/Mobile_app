# Комментарии на экране каждой стороны

Статус 2026-10-05: реализовано и принято owner; push в main разрешён. Scope: существующий hi-fi прототип, без production-интеграций.

## Сценарий и правила

1. Pickup/Delivery Review больше не содержит общий редактор двух комментариев.
2. При Sign on device контакт вводит необязательный Your comment перед своей подписью. На следующем шаге водитель видит комментарий контакта только для чтения и вводит собственный Your comment перед своей подписью.
3. Правила одинаковы для original Pickup, Supplemental Pickup и Delivery. Готовые версии и POD сохраняют оба комментария с обозначением стороны; другие версии не перезаписываются.
4. Изменение текста очищает подпись соответствующей стороны. Возврат через Edit contact comment · sign again требует повторного подписания обеими сторонами.
5. При SMS code отдельной подписи контакта нет. Contact comment (reported) вводится до OTP-проверки и означает слова контакта, записанные водителем, а не самостоятельный ввод клиента. После проверки поле заблокировано; Edit contact comment · verify again либо изменение исключения сбрасывает OTP. Комментарий водителя вводится перед его подписью и не сбрасывает OTP.
6. Пустые комментарии допустимы, UI ограничивает каждый 1 000 символами. Исключения остаются отдельными обязательными полями при повреждении/несогласии.
7. Черновики сохраняются в текущую версию localStorage. При ошибке текст остаётся на экране, переход/финальное сохранение блокируются до успешного повтора. Обновление страницы сохраняет текст, но не незавершённые подписи на устройстве.

## Проверка

- Domain tests: последовательные комментарии обеих сторон, независимость Pickup/Delivery/Supplemental, сохранение после загрузки и неизменяемость locked snapshot.
- Изолированный Chrome: подписи Pickup/Supplemental/Delivery, OTP Pickup/Delivery, неверный 111111 и успешный иной шестизначный код, сброс подписи/OTP после изменения, возврат к контакту, refresh, ошибка localStorage и повтор, сохранность original Pickup.
- Визуальный просмотр на 390 и 1440 px; ошибок приложения и горизонтального переполнения в проверенных сценариях нет.

Ограничения: подпись представлена прототипным canvas/подтверждением; OTP не отправляет SMS. Нет серверного аудита авторства, production-защиты от параллельного редактирования, проверки срока действия OTP после reload или юридически значимого подписания. Самостоятельный ввод клиента в OTP-сценарии потребовал бы отдельного клиентского канала и не входит в scope.
