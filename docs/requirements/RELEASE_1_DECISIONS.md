## Scope первого релиза

| Категория | Граница |
|---|---|
| Ядро | Home/Tasks/Scan/More; импорт подготовленного маршрута Spoke после Pre-trip; Pickup и Dropoff как отдельные handoffs; грузовые места/размеры/вес и комментарии об отсутствии данных; фотографии; подтверждения сторон; версии eBOL/POD и реальные PDF; локальная сохранность и серверная синхронизация; зарегистрированный пользователь с полным доступом |
| Сохраняемая reference база | Детали заказа/контакты/внешняя навигация, Supplemental, история, Pre/Post-trip. Их UI/UX не перепроектируется. Scope не означает, что все имитации уже реализованы в production |
| Зависит от технической проверки | Физическая печать/scan на выбранных устройствах; SMS/OTP/email через отдельный модуль Twilio; конкретные поддерживаемые устройства/версии. Device signature остаётся существующим способом подтверждения; нельзя молча объявить live OTP готовым |
| Позднее | Interstate Loading/Unloading/Trip/Interstate BOL; телефония; общая интеграция отдельного barcode-проекта. Прототип этих функций сохраняется |
| Вне Mobile App | Создание/назначение/оптимизация маршрутов и Same Day orchestration; решение проблем автомобиля. Плановые изменения приходят из внешнего процесса |
| Не утверждено | Даты, бюджет, SLA, сроки хранения, rollout, физический backend stack/deployment и полные API-контракты |

Release 1 не требует нового общего статуса RouteRun или автоматического закрытия Dropoff после Pickup. Для Local/Same Day приложение исполняет назначенные самостоятельные операции. Подтверждение отдельного правила FR не означает включение всего модуля в первый релиз.

Численные retention, session/cache TTL, capacity, RPO/RTO и поддерживаемые ОС сначала предлагает IT/QA с проверкой на реальных устройствах/нагрузке; ответ owner «best practice» не даёт оснований придумать числа или правовые сроки. Legal wording/обязанности выдачи проверяет уполномоченный владелец документов. Не требуют решения о workflow: framework, storage engine, SDK, endpoint naming.
