# Inbox: сообщения и звонки — изменение прототипа от 2026-10-27

Статус: согласовано owner в чате после анализа BA weekly от 2026-10-26, 1:03:43–1:06:44 и 1:33:16–1:33:25. Источник: https://app.fireflies.ai/view/BA-weekly::01M5W7YB7QC4QMKMWA83RTXS3G.

## Цель и scope

Водитель видит сообщения и звонки клиентов, находит пропущенные и может перезвонить с контекстом заказа. Это дополнение к FR-044/045 и UC-16, а не включение production-телефонии в Release 1. Решение R1-013 о последующем подключении телефонии сохраняется.

## Принятое поведение

- Нижняя навигация: Home / Tasks / Scan / Inbox / More. На Home карточка Inbox. Заголовок раздела — Messages & Calls; переключатель Messages / Calls. Существующие URL сохранены, Calls открывается по `#/communications?tab=calls`.
- Индикатор Inbox = количество непрочитанных сообщений + количество новых пропущенных звонков. При открытии Calls снимается признак новых пропущенных; записи остаются в истории и фильтре Missed. Просмотр не означает, что водитель перезвонил или решил вопрос клиента.
- Calls: история по убыванию времени начала, All calls / Missed, поиск по клиенту, номеру телефона и связанному/предполагаемому заказу. Пустая выдача позволяет сбросить фильтры.
- Запись: клиент, телефон, входящий/исходящий/пропущенный, дата и время звонка, длительность завершённого звонка, номер заказа, Pickup/Delivery, отдельная дата маршрута, Open order и Call back.
- Зафиксированная связь с заказом сохраняется. Для входящего номера без установленной связи ищутся заказы контакта; приоритет у заказов маршрута. Автоматически найденный контекст показывается как Suggested order. При нескольких подходящих заказах нужен явный выбор, без выбора перезвон недоступен. Если совпадений нет, контекст не выдумывается; общий набор произвольного номера вне заказа в этот инкремент не включён.
- Call back открывает существующий экран проверки клиента/заказа; Start call начинает визуальный звонок. Завершённый исходящий звонок сохраняется в истории. Отмена до соединения сохраняется как Cancelled. Уход со страницы активного звонка завершает локальный сценарий и сохраняет запись.
- Offline: историю можно читать, начало звонка недоступно. Сообщения сохраняют существующие queue/retry и quick texts. Message/Call из заказа остаются прямыми действиями.
- В списке сообщений и диалоге отдельно показана дата маршрута. Историческая запись звонка хранит свою дату маршрута, а не подменяет её датой последнего звонка.

## Границы реализации

Прототип использует localStorage (`zaberman-calls:v1`) и существующие fixtures контактов/маршрута. Входящие представлены исходными записями истории; реального приёма звонков, аудио, фоновых уведомлений, provider API и синхронизации между устройствами нет. Corporate SMS number — существующий пример, не подтверждение номера телефонии. Даты fixtures сохранены; они не означают актуальный рабочий маршрут.

В production отдельно определить provider, подтверждение связи входящего обращения с заказом, неизвестные номера, несколько подходящих заказов, события звонка и фоновую работу. Открытые OQ-11 и R1-013 сохраняются. Новый статус бизнес-обработки пропущенного звонка не вводился.

## Проверка готовности

1. Водитель открывает Inbox, переключает каналы, видит независимые индикаторы.
2. Missed показывает пропущенные после просмотра и перезагрузки; история не теряется.
3. Call back → Start → Connected → End → Back to calls добавляет исходящий звонок ровно один раз.
4. Поиск и пустая выдача работают; неоднозначный контакт требует выбора заказа.
5. Дата звонка и дата маршрута различимы; существующий SMS-сценарий доступен.
6. Пять пунктов нижней навигации доступны на узком экране.
